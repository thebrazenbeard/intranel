# Intranel V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a dependency-free `INTRANEL/1` semantic protocol library with strict parsing, canonical content identity, deterministic receiver admission, schemas, hostile test vectors, and a Bus transport profile.

**Architecture:** Implement the protocol as a small Python 3.12 standard-library package. Keep semantic validity separate from receiver-side authority/security checks. Canonical JSON provides the first exact representation; binary codecs and cryptographic implementations remain explicitly out of scope for V1.

**Tech Stack:** Python 3.12 standard library, `unittest`, JSON Schema documents, Markdown protocol specs.

**Spec:** `docs/superpowers/specs/2026-09-17-intranel-v1-design.md`

## Global Constraints

- Protocol identifier is exactly `INTRANEL/1`.
- Unknown fields and unsupported protocol versions fail closed.
- Intranel messages never create authority by transport or syntax alone.
- `origin`, `actor`, `target`, and `reply_to` remain distinct semantics.
- `message_id` and `operation_id` remain distinct identities.
- Mutating `EXECUTE` requests require operation/idempotency and authority references.
- No binary codec, encryption implementation, key management, deployment, or production cutover in V1.
- No hidden-chain-of-thought transport.
- No merge to `main` without Patrick's explicit merge authority.
